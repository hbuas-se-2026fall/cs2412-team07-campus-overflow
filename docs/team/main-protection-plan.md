# main 分支保护建议

核对日期：2026-11-03。老师仓库 API 当前显示 `main` 未受保护。本文件仅给出方案，未修改组织设置。

## 立即可启用

- 禁止删除和强制推送 main。
- 所有变更必须通过 PR，禁止直接推送。
- 至少 1 名非作者真人批准；A/B/C 业务边界变更建议 2 名批准。
- 新提交后撤销旧批准，要求解决全部 review conversations。
- 要求分支在合并前与 main 保持最新，保留线性或 squash/merge 的团队统一策略。

## 当前不能误设为已通过的门禁

Actions 已能触发，但后端目前因 Identity application 测试失败而红。不能取消检查来制造可合并状态，也不应把从未成功过的检查直接设为“已满足”。

建议顺序：

1. 先启用 PR、真人评审、禁止强推和解决会话等规则。
2. A 修复 Identity/Q&A，B 修复 Reputation，得到老师仓库首个真实全绿运行。
3. 确认稳定的检查名称后，将“后端构建与验证”“前端构建”设为 required checks。
4. 镜像、覆盖率、E2E、Sonar 尚未稳定前先作为可见检查；实际连续通过并获得团队确认后再升级为 required。

管理员操作位置：仓库 `Settings` → `Rules` → `Rulesets`（或 `Branches`）→ 新建针对 `main` 的规则。不要使用管理员绕过完成日常合并。
